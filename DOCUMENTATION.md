# 📚 Полная документация проекта BackendCourse для начинающих

## 🎯 Что это за проект?

Это **веб-приложение для управления отелями**, созданное на Python с использованием фреймворка **FastAPI**. 

**Простыми словами:** Это программа, которая позволяет через интернет:
- Просматривать список отелей
- Получать один отель по ID
- Добавлять новые отели в базу данных
- Обновлять существующие отели (полностью или частично)
- Удалять отели
- Искать отели по названию и адресу
- Получать данные постранично (пагинация)

**🔑 Ключевые концепции проекта:**
- **Repository Pattern** — разделение логики работы с БД
- **ORM → Pydantic преобразование** — автоматическое преобразование данных из БД в схемы для API
- **Разделение схем** — `HotelAdd` для создания, `Hotel` для чтения, `HotelPatch` для обновления
- **Асинхронность** — быстрая обработка множества запросов одновременно

### 1. **`src/config.py`** — Настройки приложения

**Что делает:** Хранит все настройки проекта (как подключиться к базе данных).

```python
class Settings(BaseSettings):
    DB_NAME: str      # Имя базы данных (например: "hotels_db")
    DB_HOST: str      # Адрес сервера БД (например: "localhost")
    DB_PORT: int      # Порт БД (обычно 5432 для PostgreSQL)
    DB_USER: str      # Имя пользователя БД
    DB_PASS: str      # Пароль от БД

    @property
    def db_url(self) -> str:
        # Собирает строку подключения: 
        # "postgresql+asyncpg://user:password@host:port/dbname"
        return f"postgresql+asyncpg://{self.DB_USER}:{self.DB_PASS}@{self.DB_HOST}:{self.DB_PORT}/{self.DB_NAME}"
```

**Простыми словами:**
- Это как адресная книжка с паролями
- Читает настройки из файла `.env` (который не хранится в Git для безопасности)
- Собирает из них строку подключения к базе данных

**Зачем это нужно:**
- Все настройки в одном месте
- Легко менять для разных окружений (разработка/продакшн)
- Безопасно хранить пароли (не в коде!)

### 2. **`src/database.py`** — Подключение к базе данных

**Что делает:** Настраивает соединение с базой данных PostgreSQL.

```python
# Создаем "движок" для работы с БД
engine = create_async_engine(settings.db_url)

# Создаем "фабрику" для создания сессий
async_session_maker = async_sessionmaker(bind=engine, expire_on_commit=False)

# Базовый класс для всех моделей (таблиц)
class Base(DeclarativeBase):
    pass
```

**Простыми словами:**
- `engine` — это как телефон, через который мы звоним в базу данных
- `async_session_maker` — это как телефонная будка: каждый раз, когда нужно поговорить с БД, мы создаем новую сессию
- `Base` — это родительский класс, от которого наследуются все таблицы

**Зачем это нужно:**
- Один раз настраиваем подключение, используем везде
- Асинхронность позволяет обрабатывать много запросов одновременно
- `Base` дает общие возможности всем таблицам

**Что такое сессия?**
Сессия — это временное подключение к базе данных. Представь, что это как разговор по телефону:
- Открыли сессию = подняли трубку
- Выполняем запросы = говорим
- Закрыли сессию = положили трубку

### 3. **`src/models/hotels.py`** — Модель отеля (таблица в БД)

**Что делает:** Описывает структуру таблицы `hotels` в базе данных.

```python
class HotelsOrm(Base):
    __tablename__ = "hotels"  # Имя таблицы в БД
    
    id: Mapped[int] = mapped_column(primary_key=True)  # Уникальный номер
    title: Mapped[str] = mapped_column(String(100))    # Название отеля (макс 100 символов)
    location: Mapped[str]                               # Адрес отеля
```

**Простыми словами:**
- Это как чертеж таблицы в Excel
- `id` — это номер строки (автоматически увеличивается)
- `title` — название отеля
- `location` — где находится отель

**Зачем это нужно:**
- SQLAlchemy по этой модели создает таблицу в базе данных
- Когда мы работаем с отелями в коде, мы работаем с объектами этого класса
- Автоматическая проверка типов данных

**Что такое `Mapped`?**
`Mapped[int]` означает "это поле будет типа int (целое число)". Это помогает Python понимать, какие данные можно хранить в этом поле.

**Что такое `primary_key=True`?**
Первичный ключ — это уникальный идентификатор. Как паспорт у человека: у каждого отеля свой уникальный `id`.

### 4. **`src/schemas/hotels.py`** — Схемы валидации данных

**Что делает:** Проверяет, что данные от пользователя правильные перед сохранением в БД.

```python
class HotelAdd(BaseModel):
    title: str      # Название (обязательно, строка)
    location: str   # Адрес (обязательно, строка)

class Hotel(HotelAdd):
    id: int         # ID отеля (автоматически создается в БД)
    
    model_config = ConfigDict(from_attributes=True)
    # Это позволяет создавать Hotel из ORM модели

class HotelPatch(BaseModel):
    title: None | str = None      # Название (необязательно)
    location: None | str = None   # Адрес (необязательно)
```

**Простыми словами:**
- `HotelAdd` — это форма для создания отеля (без `id`, потому что он создается автоматически)
- `Hotel` — это полная информация об отеле (включая `id`), используется для ответов API
- `HotelPatch` — это форма для частичного обновления (можно заполнить только то, что нужно изменить)

**Зачем это нужно:**
- **Валидация:** Проверяет, что пользователь не отправил мусор
- **Безопасность:** Защищает от неправильных данных
- **Удобство:** Автоматически конвертирует JSON в объект Python
- **Разделение ответственности:** `HotelAdd` для создания (без `id`), `Hotel` для чтения (с `id`)

**Пример использования:**
```python
# При создании отеля пользователь отправляет:
{
    "title": "Гранд Отель",
    "location": "Москва"
}
# Используется схема HotelAdd (без id)

# После создания БД возвращает:
{
    "id": 1,
    "title": "Гранд Отель",
    "location": "Москва"
}
# Используется схема Hotel (с id)
```

**Что такое `model_config = ConfigDict(from_attributes=True)`?**
Это настройка Pydantic, которая позволяет создавать схему `Hotel` напрямую из ORM модели `HotelsOrm`:
```python
# Без from_attributes:
hotel_orm = HotelsOrm(id=1, title="Отель", location="Москва")
hotel = Hotel(id=hotel_orm.id, title=hotel_orm.title, location=hotel_orm.location)  # Долго!

# С from_attributes:
hotel = Hotel.model_validate(hotel_orm)  # Автоматически! ✅
```

**В чем разница между Model и Schema?**
- **Model (ORM)** — описывает таблицу в базе данных (как данные хранятся)
- **Schema (Pydantic)** — описывает, какие данные можно принимать от пользователя (валидация)

### 5. **`src/repositories/base.py`** — Базовый репозиторий

**Что делает:** Базовый класс с общими методами для работы с базой данных.

```python
class BaseRepository():
    model: None  # Здесь будет указана конкретная модель (HotelsOrm, RoomsOrm и т.д.)
    schema: BaseModel = None  # Здесь будет указана Pydantic схема (Hotel, Room и т.д.)
    
    def __init__(self, session):
        self.session = session  # Сохраняем сессию БД
    
    async def get_all(self, **kwargs):
        # Получить все записи из таблицы
        query = select(self.model)  # SQL: SELECT * FROM table
        result = await self.session.execute(query)
        # Преобразуем ORM модели в Pydantic схемы
        return [self.schema.model_validate(model, from_attributes=True) 
                for model in result.scalars().all()]
    
    async def get_one_or_none(self, **filter_by):
        # Получить одну запись или None, если не найдено
        query = select(self.model).filter_by(**filter_by)  # SQL: SELECT * FROM table WHERE ...
        result = await self.session.execute(query)
        model = result.scalars().one_or_none()  # Одна ORM модель или None
        if model is None:
            return None
        # Преобразуем ORM модель в Pydantic схему
        return self.schema.model_validate(model, from_attributes=True)
    
    async def add(self, data: BaseModel):
        # Добавить новую запись
        # 1. Превращаем Pydantic модель в словарь
        # 2. Создаем SQL запрос INSERT
        # 3. Выполняем запрос
        # 4. Возвращаем созданную ORM модель
        add_stmt = insert(self.model).values(**data.model_dump()).returning(self.model)
        result = await self.session.execute(add_stmt)
        return result.scalars().one()
```

**Простыми словами:**
Это как универсальный набор инструментов для работы с любой таблицей:
- `get_all()` — "покажи мне все записи" (возвращает список Pydantic схем)
- `get_one_or_none()` — "найди одну запись по условию" (возвращает Pydantic схему или None)
- `add()` — "добавь новую запись" (возвращает ORM модель)

**Важное изменение: Преобразование ORM → Pydantic**

Раньше методы возвращали ORM модели напрямую. Теперь они автоматически преобразуют их в Pydantic схемы:

```python
# Что происходит внутри get_one_or_none():
# 1. Получаем ORM модель из БД
hotel_orm = HotelsOrm(id=1, title="Отель", location="Москва")

# 2. Преобразуем в Pydantic схему
hotel_schema = Hotel.model_validate(hotel_orm, from_attributes=True)
# Результат: Hotel(id=1, title="Отель", location="Москва")

# 3. Возвращаем схему (не ORM модель!)
return hotel_schema
```

**Зачем это нужно?**
- **Безопасность:** Не возвращаем внутренние ORM объекты наружу
- **Контроль:** Можем контролировать, какие поля возвращаются
- **Совместимость:** Pydantic схемы легко сериализуются в JSON
- **Валидация:** Гарантируем правильную структуру данных

**Детальный разбор метода `add()`:**

```python
async def add(self, data: BaseModel):
    # Шаг 1: data.model_dump() 
    # Превращает Pydantic объект в словарь:
    # HotelAdd(title="Отель", location="Москва") 
    # → {"title": "Отель", "location": "Москва"}
    
    # Шаг 2: insert(self.model).values(**data.model_dump())
    # Создает SQL запрос:
    # INSERT INTO hotels (title, location) VALUES ('Отель', 'Москва')
    # ** распаковывает словарь в именованные аргументы
    
    # Шаг 3: .returning(self.model)
    # Говорит БД: "верни мне созданную запись обратно"
    # Без этого мы бы не знали, какой id получила новая запись
    
    add_stmt = insert(self.model).values(**data.model_dump()).returning(self.model)
    
    # Шаг 4: Выполняем запрос
    result = await self.session.execute(add_stmt)
    
    # Шаг 5: Извлекаем созданную ORM модель
    return result.scalars().one()  # .one() = "дай мне одну запись"
    # Возвращается HotelsOrm(id=1, title="Отель", location="Москва")
```

**Зачем это нужно:**
- **DRY принцип:** Не повторяем один и тот же код для каждой таблицы
- **Единообразие:** Все репозитории работают одинаково
- **Простота:** Легко добавить новую таблицу, просто наследуемся от BaseRepository
- **Автоматическое преобразование:** ORM → Pydantic происходит автоматически

**Что такое `**kwargs` и `**filter_by`?**
`**` означает "распакуй словарь". Например:
```python
filter_by = {"title": "Отель", "location": "Москва"}
query.filter_by(**filter_by)
# Эквивалентно:
query.filter_by(title="Отель", location="Москва")
```

### 6. **`src/repositories/hotels.py`** — Репозиторий отелей

**Что делает:** Специфичные операции для работы с отелями (поиск, фильтрация).

```python
class HotelsRepository(BaseRepository):
    model = HotelsOrm  # Указываем, с какой ORM моделью работаем
    schema = Hotel      # Указываем, в какую Pydantic схему преобразовывать
    
    async def get_all(self, location, title, per_page, offset) -> list[Hotel]:
        # Начинаем с базового запроса
        query = select(HotelsOrm)
        
        # Если передан title, добавляем фильтр по названию
        if title:
            # ilike = поиск без учета регистра, % = любая строка
            # "%Сочи%" найдет: "Отель Сочи", "Сочи Плаза", "В Сочи"
            query = query.where(HotelsOrm.title.ilike(f"%{title}%"))
        
        # Если передан location, добавляем фильтр по адресу
        if location:
            query = query.where(HotelsOrm.location.ilike(f"%{location}%"))
        
        # Пагинация: ограничиваем количество и пропускаем записи
        query = (
            query
            .limit(per_page)    # limit(10) = покажи только 10 записей
            .offset(offset)     # offset(20) = пропусти первые 20 записей
        )
        
        result = await self.session.execute(query)
        # Преобразуем каждую ORM модель в Pydantic схему Hotel
        return [Hotel.model_validate(model, from_attributes=True) 
                for model in result.scalars().all()]
```

**Простыми словами:**
Это как умный поисковик:
- Можешь искать по названию
- Можешь искать по адресу
- Можешь искать по обоим параметрам сразу
- Результаты показываются постранично
- **Важно:** Возвращает список Pydantic схем `Hotel`, а не ORM моделей!

**Что такое `ilike`?**
`ilike` — это поиск без учета регистра (case-insensitive):
- `ilike("%сочи%")` найдет: "Сочи", "СОЧИ", "сочи", "В Сочи отдых"

**Что такое пагинация?**
Пагинация — это разбиение большого списка на страницы:
- Страница 1: записи 1-10 (offset=0, limit=10)
- Страница 2: записи 11-20 (offset=10, limit=10)
- Страница 3: записи 21-30 (offset=20, limit=10)

**Зачем переопределять `get_all()`?**
Базовый `get_all()` просто возвращает все записи. Нам нужна дополнительная логика:
- Поиск по фильтрам
- Пагинация
- Поэтому мы переопределяем метод, добавляя нужную функциональность

**Почему указываем `schema = Hotel`?**
Это нужно для базового класса `BaseRepository`. Когда мы вызываем `get_one_or_none()` из базового класса, он использует `self.schema` для преобразования ORM модели в Pydantic схему.

### 7. **`src/api/dependencies.py`** — Зависимости (вспомогательные функции)

**Что делает:** Определяет параметры пагинации для всех эндпоинтов.

```python
class PaginationParams(BaseModel):
    page: Annotated[int | None, Query(1, description="pages", ge=1)]
    # page - номер страницы (минимум 1)
    
    per_page: Annotated[int | None, Query(None, description="per page hotels", ge=1, lt=30)]
    # per_page - записей на странице (от 1 до 30)

PaginationDep = Annotated[PaginationParams, Depends()]
# Создаем зависимость, которую можно использовать в эндпоинтах
```

**Простыми словами:**
Это как стандартная форма для пагинации:
- `page` — какая страница (по умолчанию 1)
- `per_page` — сколько записей на странице (по умолчанию None, максимум 30)

**Что такое `Annotated` и `Depends()`?**
- `Annotated` — это способ добавить метаданные к типу
- `Depends()` — это FastAPI способ сказать "этот параметр нужно извлечь из запроса автоматически"

**Зачем это нужно:**
- Можно использовать пагинацию в любом эндпоинте
- Автоматическая валидация параметров
- Единообразный подход во всем приложении

### 8. **`src/api/hotels.py`** — API эндпоинты (HTTP запросы)

**Что делает:** Определяет все HTTP эндпоинты для работы с отелями.

```python
router = APIRouter(prefix="/hotels", tags=["Hotels"])
# Создаем роутер с префиксом /hotels
# Все эндпоинты будут начинаться с /hotels
```

#### **Эндпоинт 1: `GET /hotels/` — Получить список отелей**

```python
@router.get("/")
async def get_hotels(
    pagination: PaginationDep,           # Пагинация (page, per_page)
    title: str | None = Query(None, description="The title of the hotel"), 
    location: str | None = Query(None, description="The place of the hotel"),
):
    per_page = pagination.per_page or 5  # По умолчанию 5 записей на странице
    async with async_session_maker() as session:
        return await HotelsRepository(session).get_all(
            location=location,
            title=title,
            per_page=per_page,
            offset=per_page * (pagination.page - 1)  # Вычисляем offset
        )
```

**Как это работает пошагово:**

1. **Пользователь отправляет запрос:**
   ```
   GET /hotels/?title=Сочи&location=Москва&page=1&per_page=10
   ```

2. **FastAPI извлекает параметры:**
   - `title = "Сочи"`
   - `location = "Москва"`
   - `page = 1`
   - `per_page = 10`

3. **Создается сессия БД:**
   ```python
   async with async_session_maker() as session:
   ```
   Это как открыть соединение с БД. `async with` автоматически закроет его после использования.

4. **Вызывается репозиторий:**
   ```python
   HotelsRepository(session).get_all(...)
   ```
   Репозиторий выполняет поиск с фильтрами и пагинацией, возвращает список Pydantic схем `Hotel`.

5. **Возвращается результат:**
   Список отелей в формате JSON (автоматически преобразуется из Pydantic схем).

**Что такое `async with`?**
Это контекстный менеджер для асинхронных операций:
- Открывает сессию в начале блока
- Автоматически закрывает в конце (даже если произошла ошибка)
- Гарантирует, что соединение с БД будет закрыто

#### **Эндпоинт 2: `GET /hotels/hotel_id` — Получить один отель по ID**

```python
@router.get("/hotel_id")
async def get_hotel(hotel_id: int):
    async with async_session_maker() as session:
        return await HotelsRepository(session).get_one_or_none(id=hotel_id)
```

**Как это работает пошагово:**

1. **Пользователь отправляет запрос:**
   ```
   GET /hotels/hotel_id?hotel_id=1
   ```

2. **FastAPI извлекает параметр:**
   - `hotel_id = 1`

3. **Создается сессия БД**

4. **Вызывается репозиторий:**
   ```python
   HotelsRepository(session).get_one_or_none(id=hotel_id)
   ```
   - Ищет отель с `id=1` в базе данных
   - Если найден: преобразует ORM модель в Pydantic схему `Hotel` и возвращает
   - Если не найден: возвращает `None`

5. **Возвращается результат:**
   - Если найден: объект отеля в формате JSON
   - Если не найден: `null`

**Простыми словами:**
"Найди мне отель с таким-то ID и верни его данные. Если такого отеля нет, верни `null`."

**Важно:** 
- Метод `get_one_or_none()` из базового класса автоматически преобразует ORM модель в Pydantic схему `Hotel`
- Это происходит благодаря `schema = Hotel` в `HotelsRepository`

#### **Эндпоинт 3: `POST /hotels/` — Создать отель**

```python
@router.post("/")
async def create_hotel(hotel_data: HotelAdd = Body(openapi_examples={...})):
    async with async_session_maker() as session:
        # Добавляем отель в БД
        hotel = await HotelsRepository(session).add(hotel_data)
        # Сохраняем изменения (важно!)
        await session.commit()
    
    return {"status": "OK", "data": hotel}
```

**Как это работает пошагово:**

1. **Пользователь отправляет POST запрос:**
   ```json
   POST /hotels/
   {
       "title": "Отель Сочи 5 звезд у моря",
       "location": "Sochi, ul moria. 19"
   }
   ```

2. **FastAPI валидирует данные:**
   - Проверяет, что есть `title` и `location`
   - Проверяет, что это строки
   - Создает объект `HotelAdd` (без `id`, потому что он создается автоматически)

3. **Создается сессия БД**

4. **Вызывается репозиторий:**
   ```python
   HotelsRepository(session).add(hotel_data)
   ```
   - Преобразует `HotelAdd` в словарь: `{"title": "...", "location": "..."}`
   - Создает SQL запрос `INSERT INTO hotels (title, location) VALUES (...) RETURNING *`
   - Выполняет запрос
   - Возвращает ORM модель `HotelsOrm` с автоматически созданным `id`

5. **Сохраняем изменения:**
   ```python
   await session.commit()
   ```
   **ВАЖНО!** Без `commit()` изменения не сохранятся в БД!

6. **Возвращается созданный отель:**
   ```json
   {
       "status": "OK",
       "data": {
           "id": 1,
           "title": "Отель Сочи 5 звезд у моря",
           "location": "Sochi, ul moria. 19"
       }
   }
   ```
   FastAPI автоматически преобразует ORM модель в JSON.

**Почему используется `HotelAdd`, а не `Hotel`?**
- `HotelAdd` — для создания (без `id`, потому что БД создает его автоматически)
- `Hotel` — для чтения (с `id`, который уже есть в БД)

**Почему нужен `commit()`?**
В SQLAlchemy все изменения сначала находятся в "памяти" сессии. `commit()` говорит: "теперь действительно сохрани это в базу данных". Это как черновик и финальная версия:
- До `commit()` — изменения в черновике (можно отменить)
- После `commit()` — изменения сохранены навсегда

**Что такое `Body(...)`?**
`Body()` говорит FastAPI: "ожидай данные в теле запроса (не в URL)". Для POST/PUT запросов данные обычно приходят в теле запроса в формате JSON.

**Что такое `openapi_examples`?**
Это примеры для документации Swagger. Когда пользователь откроет `/docs`, он увидит эти примеры и сможет использовать их для тестирования API.

## 📝 Важные концепции для понимания

### 1. **Асинхронность (`async/await`)**

**Что это?**
Способ выполнять операции, которые занимают время (работа с БД, запросы к API), не блокируя выполнение программы.

**Простыми словами:**
Представь, что ты готовишь обед:
- **Синхронно:** Ждешь, пока вода закипит, потом режешь овощи, потом варишь
- **Асинхронно:** Ставишь воду кипятиться, пока она кипит — режешь овощи, потом варишь

**В коде:**
```python
# Синхронно (блокирует выполнение):
result = session.execute(query)  # Ждем, пока выполнится

# Асинхронно (не блокирует):
result = await session.execute(query)  # Можем делать другие дела, пока ждем
```

**Зачем это нужно?**
- Один сервер может обрабатывать тысячи запросов одновременно
- Не нужно ждать, пока один запрос закончится, чтобы начать другой

### 2. **Сессия базы данных**

**Что это?**
Временное подключение к базе данных для выполнения операций.

**Аналогия:**
Как телефонный разговор:
- Открыли сессию = подняли трубку
- Выполняем запросы = говорим
- `commit()` = "запомни то, что я сказал"
- Закрыли сессию = положили трубку

**Важно:**
- Все операции в рамках одной сессии видят друг друга
- Изменения не сохраняются, пока не вызван `commit()`
- После закрытия сессии изменения теряются (если не было `commit()`)

### 3. **Repository Pattern (Паттерн Репозиторий)**

**Что это?**
Способ разделить код на слои:
- **API слой** — обрабатывает HTTP запросы
- **Repository слой** — работает с базой данных
- **Model слой** — описывает структуру данных

**Зачем это нужно?**
- **Разделение ответственности:** Каждый слой делает свое дело
- **Тестируемость:** Легко тестировать каждый слой отдельно
- **Переиспользование:** Один репозиторий можно использовать в разных местах
- **Гибкость:** Легко поменять БД, не трогая API код

**Аналогия:**
Как в ресторане:
- **Официант (API)** — принимает заказ от клиента
- **Повар (Repository)** — готовит блюдо
- **Холодильник (Database)** — хранит ингредиенты

### 4. **Pydantic — валидация данных**

**Что это?**
Библиотека для проверки и преобразования данных.

**Что делает:**
- Проверяет типы данных (строка ли это, число ли это)
- Проверяет обязательность полей
- Преобразует JSON в объекты Python
- Преобразует объекты Python в словари (`model_dump()`)

**Пример:**
```python
class Hotel(BaseModel):
    title: str
    location: str

# Это сработает:
hotel = Hotel(title="Отель", location="Москва")  # ✅

# Это не сработает:
hotel = Hotel(title=123, location="Москва")  # ❌ Ошибка! title должен быть строкой
hotel = Hotel(location="Москва")  # ❌ Ошибка! title обязателен
```

### 5. **SQLAlchemy ORM**

**Что это?**
Объектно-реляционное отображение (ORM) — способ работать с базой данных, используя объекты Python вместо SQL запросов.

**Зачем это нужно?**
Вместо написания SQL вручную:
```sql
INSERT INTO hotels (title, location) VALUES ('Отель', 'Москва');
```

Мы пишем код на Python:
```python
hotel = HotelsOrm(title="Отель", location="Москва")
session.add(hotel)
```

**Преимущества:**
- Безопасность (защита от SQL инъекций)
- Читаемость кода
- Автоматическая работа с типами
- Легко менять БД (PostgreSQL, MySQL, SQLite)

### 6. **Преобразование ORM → Pydantic (новая концепция!)**

**Что это?**
В проекте используется паттерн, когда данные из базы данных (ORM модели) автоматически преобразуются в Pydantic схемы перед возвратом пользователю.

**Зачем это нужно?**

**Проблема без преобразования:**
```python
# Репозиторий возвращает ORM модель напрямую
hotel_orm = HotelsOrm(id=1, title="Отель", location="Москва")
# Это внутренний объект SQLAlchemy, не предназначен для API
```

**Решение с преобразованием:**
```python
# Репозиторий преобразует ORM → Pydantic
hotel_schema = Hotel.model_validate(hotel_orm, from_attributes=True)
# Результат: Hotel(id=1, title="Отель", location="Москва")
# Это чистый Pydantic объект, легко сериализуется в JSON
```

**Как это работает в коде:**

1. **В `BaseRepository`:**
   ```python
   async def get_one_or_none(self, **filter_by):
       # Получаем ORM модель из БД
       model = result.scalars().one_or_none()
       if model is None:
           return None
       # Преобразуем в Pydantic схему
       return self.schema.model_validate(model, from_attributes=True)
   ```

2. **В `HotelsRepository`:**
   ```python
   class HotelsRepository(BaseRepository):
       model = HotelsOrm  # Откуда брать данные
       schema = Hotel     # Во что преобразовывать
   ```

3. **В API:**
   ```python
   hotel = await HotelsRepository(session).get_one_or_none(id=1)
   # hotel - это уже Pydantic схема Hotel, не ORM модель!
   return hotel  # FastAPI автоматически преобразует в JSON
   ```

**Преимущества:**
- ✅ **Безопасность:** Не возвращаем внутренние ORM объекты
- ✅ **Контроль:** Можем контролировать, какие поля возвращаются
- ✅ **Гибкость:** Легко добавить вычисляемые поля в схему
- ✅ **Валидация:** Pydantic гарантирует правильную структуру данных

**Аналогия:**
Как переводчик между языками:
- ORM модель = внутренний язык (для работы с БД)
- Pydantic схема = внешний язык (для API)
- Преобразование = переводчик, который переводит один язык в другой

## ❓ Частые вопросы (FAQ)

### Q1: Зачем нужны и модели (ORM), и схемы (Pydantic)? Разве не одно и то же?

**A:** Нет, это разные вещи:

- **Model (ORM)** — описывает таблицу в базе данных:
  ```python
  class HotelsOrm(Base):
      id: Mapped[int]  # Это поле есть в БД
      title: Mapped[str]
  ```
  Используется для работы с БД.

- **Schema (Pydantic)** — описывает, какие данные можно принимать от пользователя:
  ```python
  class HotelAdd(BaseModel):
      title: str  # Пользователь должен отправить title
      location: str
      # НЕТ id, потому что БД создает его автоматически!
  
  class Hotel(HotelAdd):
      id: int  # Полная информация об отеле (для ответов API)
  ```
  Используется для валидации входящих данных и ответов API.

**Почему раздельно?**
- В БД может быть поле `created_at` (автоматически заполняется)
- Пользователю не нужно его отправлять
- Поэтому в Schema его нет, а в Model есть
- **Разные схемы для разных целей:** `HotelAdd` для создания (без `id`), `Hotel` для чтения (с `id`)

**Почему репозиторий преобразует ORM → Pydantic?**
- Безопасность: не возвращаем внутренние ORM объекты наружу
- Контроль: можем контролировать, какие поля возвращаются
- Совместимость: Pydantic схемы легко сериализуются в JSON

### Q2: Что такое `returning()` в SQL запросе?

**A:** `returning()` говорит базе данных: "после вставки записи верни мне ее обратно".

**Без `returning()`:**
```python
insert(hotels).values(title="Отель")
# БД создает запись, но мы не знаем, какой id она получила
```

**С `returning()`:**
```python
insert(hotels).values(title="Отель").returning(hotels)
# БД создает запись И возвращает ее нам, включая id
```

**Зачем это нужно?**
Чтобы знать, какой `id` получила новая запись, и вернуть полный объект пользователю.

### Q3: Почему нужен `commit()`? Разве данные не сохраняются автоматически?

**A:** Нет, в SQLAlchemy изменения сохраняются только после `commit()`.

**Как это работает:**
1. Выполняем `add()` — изменения в "памяти" сессии (транзакция открыта)
2. Вызываем `commit()` — изменения сохраняются в БД (транзакция закрыта)

**Аналогия:**
Как черновик и финальная версия:
- До `commit()` — это черновик (можно отменить через `rollback()`)
- После `commit()` — это финальная версия (сохранена навсегда)

**Зачем это нужно?**
- Можно отменить все изменения, если что-то пошло не так
- Можно выполнить несколько операций и сохранить все вместе (атомарность)

### Q4: Что такое `async with`? Чем отличается от обычного `with`?

**A:** `async with` — это асинхронный контекстный менеджер.

**Обычный `with`:**
```python
with open("file.txt") as f:
    data = f.read()
# Файл автоматически закроется
```

**Асинхронный `async with`:**
```python
async with async_session_maker() as session:
    result = await session.execute(query)
# Сессия автоматически закроется
```

**Разница:**
- `with` — для синхронных операций
- `async with` — для асинхронных операций (с `await`)

**Зачем это нужно:**
Гарантирует, что сессия БД будет закрыта даже если произошла ошибка. Без этого соединения с БД могут "висеть" и исчерпать лимит подключений.

### Q5: Что означает `**data.model_dump()`? Что такое `**`?

**A:** `**` — это оператор распаковки словаря.

**Пример:**
```python
data = Hotel(title="Отель", location="Москва")
data.model_dump()  # {"title": "Отель", "location": "Москва"}

# Без **:
insert(hotels).values({"title": "Отель", "location": "Москва"})  # ❌ Неправильно

# С **:
insert(hotels).values(**{"title": "Отель", "location": "Москва"})
# Эквивалентно:
insert(hotels).values(title="Отель", location="Москва")  # ✅ Правильно
```

**Простыми словами:**
`**` превращает словарь в именованные аргументы функции.

### Q6: Что такое `ilike`? Чем отличается от `like`?

**A:** `ilike` — это поиск без учета регистра (case-insensitive).

**`like` (с учетом регистра):**
```python
query.where(HotelsOrm.title.like("%сочи%"))
# Найдет: "отель в сочи"
# НЕ найдет: "Отель в Сочи", "СОЧИ"
```

**`ilike` (без учета регистра):**
```python
query.where(HotelsOrm.title.ilike("%сочи%"))
# Найдет: "отель в сочи", "Отель в Сочи", "СОЧИ", "В Сочи отдых"
```

**Зачем это нужно:**
Пользователь может искать "сочи", "Сочи" или "СОЧИ" — все варианты должны работать.

### Q7: Что такое пагинация и зачем она нужна?

**A:** Пагинация — это разбиение большого списка на страницы.

**Проблема без пагинации:**
Если в БД 10,000 отелей, и пользователь запрашивает все сразу:
- Медленно загружается
- Много трафика
- Плохой UX

**Решение — пагинация:**
Показываем по 10 отелей на странице:
- Страница 1: отели 1-10
- Страница 2: отели 11-20
- И так далее

**В коде:**
```python
query.limit(10).offset(0)   # Первая страница (10 записей, пропустить 0)
query.limit(10).offset(10)   # Вторая страница (10 записей, пропустить 10)
query.limit(10).offset(20)   # Третья страница (10 записей, пропустить 20)
```

### Q8: Что такое `Depends()` в FastAPI?

**A:** `Depends()` — это способ автоматически извлечь параметры из запроса.

**Без `Depends()`:**
```python
@router.get("/")
async def get_hotels(page: int = Query(1), per_page: int = Query(10)):
    # Нужно указывать Query для каждого параметра
```

**С `Depends()`:**
```python
@router.get("/")
async def get_hotels(pagination: PaginationDep):
    # FastAPI автоматически создаст PaginationParams из запроса
    # И передаст его в функцию
```

**Зачем это нужно:**
- Переиспользование логики (пагинация везде одинаковая)
- Автоматическая валидация
- Чище код

### Q9: Почему `BaseRepository` не может использоваться напрямую?

**A:** Потому что у него не установлены атрибуты `model` и `schema`.

**Проблема:**
```python
BaseRepository(session).add(data)  # ❌ Ошибка! model = None
# Когда код попытается сделать insert(None), будет ошибка

BaseRepository(session).get_one_or_none(id=1)  # ❌ Ошибка! schema = None
# Не знаем, в какую схему преобразовывать
```

**Решение:**
```python
class HotelsRepository(BaseRepository):
    model = HotelsOrm  # Указываем конкретную ORM модель
    schema = Hotel      # Указываем конкретную Pydantic схему

HotelsRepository(session).add(data)  # ✅ Работает!
HotelsRepository(session).get_one_or_none(id=1)  # ✅ Работает!
```

**Аналогия:**
`BaseRepository` — это как шаблон формы без указания, какая это форма. Нужно создать конкретную форму (HotelsRepository) и указать, для чего она (model) и как ее заполнять (schema).

**Зачем нужен `schema`?**
Базовый класс использует `self.schema` для автоматического преобразования ORM моделей в Pydantic схемы:
```python
# В BaseRepository.get_one_or_none():
return self.schema.model_validate(model, from_attributes=True)
# Без указания schema это не сработает!
```

### Q10: Что происходит, если не вызвать `commit()`?

**A:** Изменения не сохранятся в базе данных!

**Пример:**
```python
async with async_session_maker() as session:
    hotel = await HotelsRepository(session).add(hotel_data)
    # НЕТ commit()!
# Сессия закрывается, изменения теряются
```

**Результат:**
- Запрос выполнится без ошибок
- Но в БД ничего не появится
- При следующем запросе данные исчезнут

**Правильно:**
```python
async with async_session_maker() as session:
    hotel = await HotelsRepository(session).add(hotel_data)
    await session.commit()  # ✅ Теперь сохранится!
```

### Q11: Зачем нужна схема `HotelAdd`, если есть `Hotel`?

**A:** Это разделение ответственности для разных операций.

**Проблема без `HotelAdd`:**
```python
# Если использовать Hotel для создания:
class Hotel(BaseModel):
    id: int        # ❌ Пользователь должен отправлять id?
    title: str
    location: str

# Пользователь должен отправлять:
{
    "id": 1,  # ❌ Но id создается автоматически в БД!
    "title": "Отель",
    "location": "Москва"
}
```

**Решение с `HotelAdd`:**
```python
# Для создания (без id):
class HotelAdd(BaseModel):
    title: str
    location: str

# Для чтения (с id):
class Hotel(HotelAdd):
    id: int

# Пользователь отправляет:
{
    "title": "Отель",  # ✅ Только нужные поля
    "location": "Москва"
}
# БД автоматически создает id
```

**Зачем это нужно:**
- ✅ **Чистота API:** Пользователь не должен знать про внутренние детали (id)
- ✅ **Безопасность:** Пользователь не может указать свой id (может быть конфликт)
- ✅ **Понятность:** Ясно, что для создания нужны только `title` и `location`

**Когда что использовать:**
- `HotelAdd` — для создания отеля (POST запросы)
- `Hotel` — для чтения отеля (GET запросы, ответы API)
- `HotelPatch` — для частичного обновления (PATCH запросы)

### Q12: Зачем преобразовывать ORM модели в Pydantic схемы? Разве нельзя вернуть ORM напрямую?

**A:** Технически можно, но это плохая практика.

**Проблема без преобразования:**
```python
# Репозиторий возвращает ORM модель напрямую
async def get_one_or_none(self, **filter_by):
    query = select(self.model).filter_by(**filter_by)
    result = await self.session.execute(query)
    return result.scalars().one_or_none()  # Возвращает HotelsOrm

# В API:
hotel = await HotelsRepository(session).get_one_or_none(id=1)
# hotel - это HotelsOrm (внутренний объект SQLAlchemy)
return hotel  # FastAPI попытается сериализовать, но могут быть проблемы
```

**Проблемы:**
- ❌ ORM модели содержат внутренние атрибуты SQLAlchemy (не нужны в API)
- ❌ Могут быть проблемы с сериализацией в JSON
- ❌ Нет контроля над тем, какие поля возвращаются
- ❌ Связанность с SQLAlchemy (если поменяем ORM, сломается API)

**Решение с преобразованием:**
```python
# Репозиторий преобразует ORM → Pydantic
async def get_one_or_none(self, **filter_by):
    model = result.scalars().one_or_none()
    if model is None:
        return None
    return self.schema.model_validate(model, from_attributes=True)
    # Возвращает Hotel (Pydantic схему)

# В API:
hotel = await HotelsRepository(session).get_one_or_none(id=1)
# hotel - это Hotel (чистый Pydantic объект)
return hotel  # ✅ Легко сериализуется в JSON
```

**Преимущества:**
- ✅ Чистые объекты без внутренних атрибутов SQLAlchemy
- ✅ Легкая сериализация в JSON
- ✅ Контроль над возвращаемыми полями
- ✅ Независимость от ORM (можно поменять ORM, схема останется)

**Аналогия:**
Как упаковка товара:
- ORM модель = товар на складе (со всеми внутренними метками)
- Pydantic схема = товар в красивой упаковке для клиента
- Преобразование = процесс упаковки

## 🐛 Частые ошибки и их решения

### Ошибка: "result is not defined"
**Причина:** Используется переменная `result`, которая не была создана.
**Решение:** Убедись, что перед использованием `result` ты выполнил `result = await session.execute(query)`.

### Ошибка: "'BaseRepository' object has no attribute 'model'"
**Причина:** Используется `BaseRepository` напрямую вместо конкретного репозитория.
**Решение:** Используй `HotelsRepository` вместо `BaseRepository`.

### Ошибка: Изменения не сохраняются в БД
**Причина:** Забыл вызвать `session.commit()`.
**Решение:** Добавь `await session.commit()` после операций изменения данных.

### Ошибка: "Connection refused"
**Причина:** PostgreSQL не запущен или неправильные настройки в `.env`.
**Решение:** Проверь, что PostgreSQL запущен и настройки в `.env` правильные.
